## 推荐的改动路径

### 修改一个页面展示

先找 `ui/app.py` 中对应工作区的 `render_*` 函数；如果需要把后端字典安全转成表格/文本，再看 `src/cockpit_view_model.py`。不要在 UI 内复制业务计算；应把规则放在 `src/business_rules.py` 或对应节点。

### 增加一个 Agent 能力

先明确它是“解释/调查”还是“确定性业务决策”。前者可放入 `src/agents/`；后者应优先放入业务规则。然后扩展 `src/state.py` 的结构化状态、在 `src/graph.py` 添加节点和边，并补充 `tests/`。若需要外部动作，不要直接暴露给 LLM，应先经过边界 schema、审批/门禁与幂等设计。

### 新增一个知识文件

放到 `data/knowledge/`，补充 metadata，执行 `python -m src.rag.ingest`，再用页面证据区验证。不要将未审核合同文本直接标记为 `active`。

### 修改履约或反馈条件

采购状态机主要在 `src/procurement_adapter.py` 与 `src/db_service.py`；可反馈资格和页面诊断还涉及 `src/cockpit_view_model.py`、`ui/app.py`、长期记忆节点。改动前先看相应测试。

## 开发与验证命令

```powershell
# 初始化本地数据库
python src/db_init.py

# 重建向量索引
python -m src.rag.ingest --rebuild

# 启动 UI
streamlit run ui/app.py

# 运行单元测试
python -m unittest discover -s tests -v

# 运行离线 Agent 场景评测（需要完整 LLM 环境）
python src/evaluation/runner.py

# 运行 RAG 检索评测（需先存在索引）
$env:PYTHONPATH='src'; python -m evaluation.retrieval_evaluator --output artifacts/evaluations/rag_retrieval.json
```

macOS/Linux 最后一条可写为：

```bash
PYTHONPATH=src python -m evaluation.retrieval_evaluator --output artifacts/evaluations/rag_retrieval.json
```

## 修改后应检查

1. `python -m unittest discover -s tests -v`。
2. 重新启动 Streamlit（文件监视已关闭）。
3. 对涉及数据的改动，在干净或备份后的 SQLite 文件上验证。
4. 对涉及知识的改动，重新构建索引并检查页面引用。
5. 对涉及审批/执行的改动，至少覆盖批准、拒绝、过期/数据变化阻断三个路径。

不要把 `.env`、`data/supply_chain.db`、`data/workflow_checkpoints.sqlite`、向量索引或含真实 Key 的日志提交到版本库。
