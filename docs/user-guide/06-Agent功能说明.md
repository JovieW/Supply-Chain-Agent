# Agent 功能说明

## 从用户视角：Agent 做了什么

点击“生成新方案”后，系统不是让模型直接决定采购金额，而是按受约束流程完成以下工作：

1. 读取当前产品的库存、历史需求、供应商、在途采购和业务规则。
2. 从已发布知识库检索可能相关的库存策略、合同、物流制度和历史事件。
3. 由 LLM 在白名单内选择少量**只读**调查工具，补充库存位置、预测、在途、供应商比较、知识检索或压力测试信息。
4. 用确定性计算形成需求预测、补货点、数量、候选供应商、物流方案与风险等级。
5. 由 LLM 生成受上下文约束的说明，并结合规则进行有限轮次反思。
6. 根据风险门禁自动执行本地模拟采购，或暂停等待人工审批。

因此，用户获得的是“带依据和约束的建议”，而不是可自由下单的聊天机器人。

## 输入、输出与操作边界

| 内容 | 来源 | 用户可见位置 | 是否会改数据 |
|---|---|---|---:|
| 业务快照 | SQLite | 指标、方案、档案 | 否 |
| 知识证据 | Chroma 索引 | 方案依据与运行记录 | 否 |
| 工具调查 | 只读工具白名单 | 运行记录 | 否 |
| 补货计划 | 业务规则 + LLM 解释 | 方案卡 | 生成时写本地运行/记忆 |
| 执行采购 | 决策门禁后 `ProcurementAdapter` | 状态、履约页 | 是，本地模拟采购单 |
| 审批 | 人工点击 + 检查点恢复 | 审批任务 | 是，本地审批与工作流状态 |
| 结果反馈 | 人工录入 | 结果反馈 | 是，本地记忆与反馈 |

## 哪些只是建议，哪些会执行

- 生成方案本身是建议；未通过门禁前不创建采购单。
- 中低风险且检查通过的方案可以自动创建**本地模拟**采购单。
- 高风险或反思升级方案必须先审批。
- 系统不连接真实采购、库存、物流或支付系统，不会向企业外部发送订单。

## 给开发者看的技术说明

### Workflow 与 Agent

`src/graph.py:create_supply_chain_graph` 按固定骨架编排节点：数据读取、知识检索、只读调查、需求、记忆召回、库存；库存计划完成后，风险与物流 Agent 并行分析，二者全部完成后再汇合到协调、反思、门禁、记忆持久化和审批/执行。工具调查与需求分析仍保持顺序。LangGraph 的价值主要在于保存状态、并行分支汇合、条件路由和审批中断恢复，而不是 LLM 自由编排全流程。

### 多职责节点

`src/agents/` 中的 demand、inventory、risk、logistics、coordinator、reflection 与 tool_investigator 有不同职责。核心数值和安全约束集中在业务规则与节点；LLM 主要负责受限解释、工具选择、总结和批评。因此它是“受治理的 LLM 辅助工作流”，不要宣传为完全自主采购 Agent。

### RAG

`src/rag/` 将 Markdown/TXT/PDF/DOCX 分块、embedding 并写入 Chroma；检索阶段按文档状态、适用范围和有效期过滤，返回证据及引用。应用运行时不会重建索引。

### Tool Calling

`src/autonomous_tools.py` 定义参数模型和只读工具，`tool_investigator.py` 对模型选择做白名单、次数和超时限制。写采购单不属于 LLM 可调用工具，而是在后续门禁节点由代码执行。

### Reflection

`reflection_agent.py` 与 `reflection_rules.py` 检查前一版计划。最多轮数由 `AGENT_MAX_REFLECTION_ROUNDS` 限制；需要升级时交由审批，而不是无限重试。

### Human-in-the-loop 与 Memory

`human_approval` 节点使用 LangGraph interrupt 保存检查点，批准使用 `Command(resume=...)` 恢复。`long_term_memory` 节点把决策和已反馈结果保存到 SQLite；只有结果已录入的案例才会作为后续结果经验召回候选。
