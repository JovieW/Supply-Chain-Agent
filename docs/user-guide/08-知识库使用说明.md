# 知识库使用说明

## 知识库是什么

知识库为决策提供企业制度和历史证据，而不是替代实时库存数据库。默认目录 `data/knowledge/` 包含库存策略、物流策略、供应商 SLA、审批政策、供应商框架合同，以及港口罢工等历史事件文件。

## 支持的文件和索引链路

已支持 `.md`、`.txt`、`.pdf`、`.docx`。`src/rag/ingest.py` 会读取文件、分块、生成 embedding 并写入本地 Chroma 索引（默认 `data/vector_store/`）。检索会取 Top-K 候选并结合文档状态、适用产品/供应商/区域及有效期等 metadata 做过滤；页面显示来源、片段、分数和版本等证据。

## 新增一份知识文件

1. 将文件放进 `data/knowledge/` 或其子目录，例如 `data/knowledge/contracts/`。
2. Markdown/TXT 建议在文件顶部使用 front matter，记录文档身份和适用范围。例如：

   ```yaml
   ---
   document_id: logistics-sop-2026
   version: v1.0
   status: active
   effective_from: 2026-01-01
   owner: supply-chain
   product_ids: [1, 2]
   supplier_ids: [1]
   regions: [CN-East]
   ---
   ```

   `status` 应为 `active`；`draft` 或 `retired` 文档不会作为正式证据。适用范围字段可省略，但省略后过滤能力会更弱。
3. 增量构建索引：

   ```powershell
   python -m src.rag.ingest
   ```

4. 若首次构建、修改了切分/embedding 配置，或希望彻底重建：

   ```powershell
   python -m src.rag.ingest --rebuild
   ```

5. 重启或重新运行方案，在“决策工作台 → 查看方案依据与运行记录 → 企业知识库证据”查看是否被引用。

## 使用注意事项

- 应用请求不会自动扫描文件或重建索引；新增文件后必须手动 ingest。
- 默认本地 embedding 模型首次下载需要网络，但不要求 LLM API Key。若选择 `RAG_EMBEDDING_PROVIDER=dashscope`，则 embedding 也依赖 DashScope Key。
- RAG 是辅助证据，不是合同真实性校验系统。错误、过期或范围标记不全的文档可能导致不恰当召回；高风险决策仍应人工审核。
- 当前没有网页上传、知识审核后台、在线版本管理或 reranker 配置界面；需通过文件和命令行管理。
