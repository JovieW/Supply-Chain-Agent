# 典型案例

以下案例使用仓库中真实的内置产品和本地展示脚本。实际数值会随本地数据库状态、模型输出和日期变化。

## 案例一：标准件 A 的稳定需求补货

**背景**：左侧选择“标准件 A（稳定需求）”。初始化数据包含相对稳定的需求、在手库存和在途采购。

**操作步骤**：

1. 启动完整模式，选择标准件 A。
2. 点击“生成新方案”。
3. 查看库存位置、可用天数、28 天需求与方案卡。
4. 展开“查看方案依据与运行记录”，核对库存政策或合同证据。

**系统行为**：系统读取需求和库存，按规则计算补货点与缺口，再结合供应商/物流风险给出可执行或保持建议。风险较低时可能直接在本地创建采购单。

**关注点**：不要只看“建议数量”；应同时检查预计缺口、风险调整总成本和引用知识是否适用于该产品。

## 案例二：专用件 C 的高风险方案与人工审批

**背景**：选择“专用件 C（高缺货风险）”。初始化数据中其库存低且在途/供应风险更突出，适合演示风险门禁，但最终是否进入审批仍由当轮规则和数据决定。

**操作步骤**：

1. 选择专用件 C，生成方案。
2. 若状态为“等待审批”，点击“前往审批任务”。
3. 打开待办，核对风险和金额，填写意见后批准。
4. 返回“结果反馈”，确认出现活动采购单并推进履约状态。

**系统行为**：审批前不会创建采购单。批准后从检查点恢复，并重新校验业务快照；若数据已变化，可能显示阻断，必须重新生成方案。

**关注点**：这演示的是受治理的本地工作流，不是自动向真实供应商下单。

## 案例三：展示履约、反馈与结果记忆

**背景**：希望不依赖一次新的 LLM 运行就看到完整闭环数据。

**操作步骤**：

1. 配置可用的 `MEMORY_FEEDBACK_USERS` 后运行：

   ```powershell
   python demo/seed_showcase_data.py --feedback-email planner@example.com
   ```

2. 启动 `ui/app.py`，打开“结果反馈”。
3. 在“采购履约”选择仍活动的展示采购单，按页面允许的状态继续确认、发运、收货、质检和关闭。
4. 采购单关闭后，在“实际结果反馈”填写实际结果，反馈邮箱填写上一步的白名单邮箱。
5. 在“已闭环历史结果”查看已有及新增的结果记录。

**系统行为**：脚本会绕过 LLM 和审批直接写本地展示数据；`QC_ACCEPTED` 会增加本地库存，反馈会生成 `OUTCOME_RECORDED` 记忆。

**关注点**：脚本是 Demo 数据工具，会修改当前 `data/supply_chain.db`，不应用于真实业务库。
