# 指标解释

## 库存与需求

| 指标 | 定义与理解 | 高/低意味着什么 | 对决策的影响 |
|---|---|---|---|
| 在手库存 | 当前仓库中可计入的实际库存数量 | 高：短期缓冲较多；低：更易缺货 | 是补货缺口的基础 |
| 库存位置 | 在手库存 + 已确认在途量 − 已承诺/需求占用量 | 比在手库存更接近“能保障的净供给” | 用于判断是否到达补货点 |
| 可用天数 | 可用库存按预测日均需求可支撑的天数 | 低：紧急程度高；高：可延后补货 | 影响运输方式和风险判断 |
| 28 天预测需求 | 未来 28 天的规则预测总需求 | 高：未来消耗压力大 | 影响安全库存、缺口和数量 |
| 需求波动 | 历史需求变化程度 | 高：预测不确定性更大 | 通常提高缓冲和风险关注度 |
| 安全库存 | 为应对需求/交期不确定性保留的缓冲库存 | 过低易断供，过高占用资金 | 是补货点组成部分 |
| 动态补货点 | 在预计交期内的需求 + 安全库存 | 库存位置低于它，通常应补货 | 触发补货建议 |
| 预计缺口 | 预测周期内供给无法覆盖需求的数量 | 正值越大，断供风险越高 | 驱动建议采购数量 |

概念区别：**在手库存**只问仓库“现在有多少”；**库存位置**还考虑在途和已被需求占用的部分，因此更适合作补货判断。

## 供应商、成本与履约

| 指标 | 定义与理解 | 对决策的影响 |
|---|---|---|
| 建议供应商 | 在可供选项中按规则、合同/资质、成本、质量、交期和风险选择的方案 | 决定本地采购单的供应商 |
| 交期 / Lead time | 从下单到可用的预计天数 | 交期越长，越需要提前补货或使用更快运输 |
| 在途采购 | 已创建但尚未完全入库的本地采购单供给 | 增加库存位置，避免重复补货 |
| 实际收货量 | 履约阶段记录的到货数量 | 与计划数量差异会影响结果反馈 |
| 质量拒收量 | 到货但未通过质检的数量 | 拒收越多，可用供给越少 |
| 风险调整总成本 | 基础采购/运输成本叠加风险相关影响后的比较值 | 不只追求最低报价，而是在成本与可靠性间权衡 |
| 服务水平 | 反馈中记录的需求被满足程度 | 用于判断方案效果与沉淀经验 |

## 风险、审批与执行

| 指标 | 定义与理解 | 影响 |
|---|---|---|
| 风险等级 | 规则和风险节点给出的 LOW / MEDIUM / HIGH 等分类 | 决定是否可自动走到本地执行 |
| 风险分数 | 对供应、物流、库存暴露等因素的汇总分数 | 当前高分通常进入审批门禁 |
| 风险原因 | 导致该等级的可解释条目 | 审批人应逐项核对 |
| 审批有效期 | 审批请求在多长时间内可恢复 | 过期后不能继续旧方案 |
| 执行前校验 | 审批后/执行前重新读取快照的验证 | 防止基于过时库存执行 |
| 采购单状态 | `CREATED` 到 `CLOSED` 的本地履约生命周期 | 决定何时可以反馈结果 |

## 结果反馈与记忆

| 指标 | 定义与理解 | 影响 |
|---|---|---|
| 实际交期 | 实际从执行到到货/可用的天数 | 可揭示计划交期是否偏差 |
| 实际成本 | 真实或演示录入的总成本 | 用于方案效果比较 |
| 缺货量 | 该次周期内未满足的需求量 | 高值表示服务失败或缓冲不足 |
| 结果状态 | `OUTCOME_RECORDED` 表示结果已写入 | 后续运行可把它作为经验候选 |
| 长期记忆 | 已持久化的决策和结果记录 | 只有有结果的记录才更有业务学习价值 |

本项目具体计算在 `src/business_rules.py` 等模块中。指标用于辅助决策，不应替代采购负责人对合同、预算和现场异常的判断。
