# 项目介绍

## 一句话介绍

这是一个面向供应链计划人员的本地决策助手：它结合库存、需求、供应商和在途数据，生成可解释的补货建议，并把高风险方案送入人工审批和后续履约反馈流程。

## 100 字介绍

系统以本地 SQLite 中的供应链数据为基础，计算需求预测、库存缺口、补货点、候选供应商及风险调整成本。LLM 负责解释、检索企业 SOP/合同/历史事件、选择受限的只读调查工具并做有限反思；确定性的业务规则负责数量、供应商、执行前校验与状态流转。高风险方案会暂停等待审批，采购履约和实际结果可写回本地记录。

## 完整项目介绍

适合使用者是供应链计划员、采购协调人员及审批负责人。用户选择产品后可生成补货方案，查看“为什么要补、补多少、向谁采购、有什么风险、依据哪份制度或合同”。当风险门禁要求审批时，系统会保存工作流并在批准后恢复执行；执行在本项目中是创建本地模拟采购单，而不是真实下单。到货、质检和实际业务结果可继续录入，形成可被后续方案参考的历史经验。

## 已实现的核心功能

- **决策工作台**：针对 3 个内置产品生成需求、库存、供应商、物流与风险建议。
- **知识库检索**：从 `data/knowledge/` 的 SOP、合同和历史事件中检索证据；索引使用本地 Chroma。
- **受限 Agent 调查**：LLM 只能选择库存、预测、在途、供应商、知识检索和情景模拟等只读工具。
- **规则与反思**：数量与执行由业务规则计算；LLM/规则联合检查方案，最多有限轮次修订。
- **Human-in-the-loop**：高风险方案可通过 LangGraph interrupt 暂停，批准或拒绝后继续/结束本地流程。
- **采购履约与结果反馈**：本地采购单可经历确认、发运、收货、质检、关闭；关闭后可录入实际结果并沉淀结果记忆。

## 不应误解为已实现的能力

- 不是可直接操作真实企业采购、仓储或物流系统的机器人。
- 没有登录页、SSO、真实 RBAC 或多租户隔离；本地审批身份由服务端环境变量模拟。
- 没有 Docker、Redis、消息队列、定时调度器或独立 API 服务入口。
- 静态演示页中的图表和“证据”是固定展示，不代表真实 Agent 运行。
