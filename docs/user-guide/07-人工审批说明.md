# 人工审批说明

## 何时会需要审批

风险规则在 `src/nodes/decision_gate.py` 中判断。当前规则通常将高风险（风险分数不低于 4）或反思要求升级的方案送入审批；中低风险且执行校验通过时可走本地自动执行。审批阈值、有效期和高金额角色门槛由 `.env` 的 `HITL_*` 配置控制。

## 审批前是否已执行

**没有。** 需要审批的流程在 `src/nodes/human_approval.py` 的 interrupt 处暂停，采购单尚未创建。计划、风险、审批请求和检查点会保存到本地 SQLite 文件。

## 操作步骤

1. 在左侧进入“审批任务”。
2. 从“待审批任务”选择一项，点击“打开任务”。
3. 核对产品、建议数量、供应商、风险原因和失效时间。
4. 填写可选审批意见。
5. 点击“批准并恢复执行”或“拒绝方案”。

批准后，系统使用同一工作流检查点恢复，在 `execution` 节点重新读取实时快照并验证；通过后才创建本地模拟采购单。拒绝后该流程结束，不会生成采购单。

## 谁可以审批

当前不是登录系统。服务端通过：

- `HITL_CURRENT_ACTOR_EMAIL`：当前本地演示审批人；
- `HITL_APPROVER_BINDINGS`：邮箱到 `supply_chain_manager`、`procurement_director` 或 `admin` 的绑定；
- `HITL_DIRECTOR_COST_THRESHOLD`：高金额方案可能要求更高审批角色。

UI 不接收用户自行提交的角色字符串。这个做法适合本地演示，不等同于企业 SSO、RBAC、组织架构或电子签名。

## 批准、拒绝、过期和数据变化

| 情况 | 系统结果 | 用户下一步 |
|---|---|---|
| 批准且复核通过 | 恢复流程并创建本地采购单 | 去“结果反馈”跟踪履约 |
| 拒绝 | 方案结束 | 根据意见重新生成新方案 |
| 审批超时 | 不再可恢复 | 重新生成方案 |
| 批准前库存/供应商等关键数据变化 | 执行前校验阻断为 stale/blocked | 刷新数据后重新生成方案 |
| 无权限或身份未配置 | 审批操作失败 | 修正 `.env` 绑定后重启 |

当前不提供“在同一审批任务中修改数量后再批准”的协商编辑流程；应拒绝或阻断后重新生成可审计的新方案。

## 实现程度

本地的“暂停 → 持久化检查点 → 人工决定 → resume”链路是已实现的。但审批身份、采购执行和审计存储均为本地模拟，未对接真实企业身份、通知、审批流或采购系统。
