# 故障排查

## 页面打不开或端口被占用

**可能原因**：Streamlit 未启动、当前目录不对，或 8501 被占用。

**检查方法**：终端确认出现 `You can now view your Streamlit app`；Windows 可执行 `netstat -ano | Select-String 8501`。

**解决办法**：在项目根目录运行 `streamlit run ui/app.py`；或使用 `streamlit run ui/app.py --server.port 8502` 并访问对应地址。

## `ModuleNotFoundError` / 安装依赖失败

**可能原因**：未激活 Python 3.12 虚拟环境，或 pip 使用了其他 Python。

**检查方法**：执行 `python --version`、`python -m pip --version`。

**解决办法**：重新激活 `.venv`/conda 环境，使用 `python -m pip install -r requirements.txt`，不要混用系统 pip。

## Streamlit 监视器报 `No module named 'torchvision'`

**可能原因**：Streamlit 探测 `transformers` 的可选图像模块时触发了 ZoeDepth/torchvision 依赖，并非本项目业务代码主动使用该图像模型。

**检查方法**：确认异常来自 `streamlit/watcher` 与 `transformers.models.zoedepth`。

**解决办法**：仓库已在 `.streamlit/config.toml` 配置 `fileWatcherType = "none"`。重启后仍有问题时显式运行：

```bash
streamlit run ui/app.py --server.fileWatcherType none
```

仅当其他用途确实需要 torchvision 时，才按本机 PyTorch 版本安装匹配的 torchvision；不要为这个监视器问题盲目安装 GPU 包。

## Agent 报 API Key、401、403 或配额耗尽

**可能原因**：Key 无效、provider 配置不一致、免费额度耗尽，或模型无权限。

**检查方法**：检查 `.env` 的 `LLM_PROVIDER` 与对应 Key；查看供应商控制台返回的错误码，例如 `AllocationQuota.FreeTierOnly` 表示免费额度/免费模式限制。

**解决办法**：补充或更换有效额度，或改用已配置的 provider/model；随后重启 Streamlit。代码不能绕过服务商余额或权限限制。

## RAG 没有返回结果 / Chroma 索引错误

**可能原因**：未构建索引、知识文件路径不对、embedding 模型首次下载失败，或文档 metadata 被过滤。

**检查方法**：确认 `data/vector_store/` 与 `RAG_PERSIST_DIR` 一致，运行 ingest 命令观察报错。

**解决办法**：

```bash
python -m src.rag.ingest --rebuild
```

确认网络可下载本地模型；若用 DashScope embedding，配置有效 `DASHSCOPE_API_KEY`。检查 Markdown/TXT 文档的 `status: active` 和适用范围。

## 审批任务加载失败或批准无法恢复

**可能原因**：审批人绑定缺失、审批已过期、检查点文件不可写，或恢复前业务数据发生变化。

**检查方法**：检查 `.env` 中 `HITL_CURRENT_ACTOR_EMAIL`、`HITL_APPROVER_BINDINGS`、`HITL_CHECKPOINT_DB`，并查看页面的任务状态/运行记录。

**解决办法**：使用模板中的本地演示邮箱绑定并重启；确保 `data/` 可写。过期或 stale 的方案不能强行恢复，应重新生成。

## 没有待反馈结果

**可能原因**：采购单未 `CLOSED`、没有关联执行记忆、结果已经反馈，或不是 HOLD 场景。

**检查方法**：先在“采购履约”查看订单状态，再阅读结果反馈页诊断信息。

**解决办法**：完成合法状态流转至 `CLOSED`，或运行 `demo/seed_showcase_data.py` 获得展示记录。

## 反馈邮箱不被接受

**可能原因**：填写邮箱不在 `MEMORY_FEEDBACK_USERS`。

**解决办法**：把邮箱加入逗号分隔白名单，重启 Streamlit，再提交。

## DataFrame / Arrow 类型错误

**可能原因**：本地数据库或自定义数据把数字和格式化字符串混在同一列，Streamlit 转 Arrow 失败。

**检查方法**：错误会包含列名，如“本轮值”。

**解决办法**：恢复/初始化示例数据，或在自行扩展数据展示时保证同一列统一为数值或字符串。该问题通常来自自定义数据，不要把货币格式字符串与整数混存。

## JSON 输出或模型响应格式错误

**可能原因**：模型不兼容、网络超时，或模型未遵守受限输出格式。

**检查方法**：查看 `data/agent_traces.jsonl` 和页面运行记录。

**解决办法**：换用兼容的聊天模型、降低网络问题、重新运行；工具节点会降级记录失败，但部分 Agent LLM 调用失败会使本轮无法完成。

## Docker、数据库服务、Redis 连接问题

**说明**：当前项目没有 Docker、Redis 或外部数据库服务依赖。默认是本地 SQLite。若你自行改为外部服务，这是自定义部署问题，不在当前仓库的受支持启动范围内。
