# 页面功能说明

## 左侧控制区

- **工作区**：在四个业务页面之间切换，不代表用户角色切换。
- **当前产品**：选择本轮分析对象；内置为产品 1、2、3。
- **生成新方案**：启动一次决策工作流。它不会覆盖已完成的审批或历史记录，但会写入新的本地运行记录。

## 决策工作台

**用途**：生成并理解一份补货方案；适合计划员或采购协调人。

主要区域：

- **库存与需求指标**：在手库存、库存位置、可用天数、28 天预测需求。
- **方案卡**：显示补货/保持等建议、建议供应商、数量、运输方式和解释。
- **业务影响表**：安全库存、动态补货点、预计缺口、风险调整总成本等计算结果。
- **风险与操作**：显示风险等级、分数、原因与审批规则；需要审批时可跳转审批工作区，已执行时可跳转结果反馈。
- **方案依据与运行记录**（展开区）：企业知识库证据及引用、反思结论、只读工具调用概况、工作流轨迹和本地观测事件。

数据主要来自 SQLite 与已发布 Chroma 索引。LLM 文本用于解释、工具选择和反思；核心采购数量/供应商并非由页面手工填写或 LLM 自由决定。

## 审批任务

**用途**：处理暂停的高风险决策；适合在本地演示中被配置为审批人的业务负责人。

- **待审批任务**：选择任务后点击“打开任务”。
- **任务详情**：显示方案、风险、审批有效期和当前服务端识别的审批人。
- **批准并恢复执行**：恢复同一个 LangGraph 检查点，再做执行前校验并创建本地模拟采购单。
- **拒绝方案**：记录意见并结束流程；不会创建采购单。
- **最近审批记录**：查看本地审批记录。 

UI 不允许选择角色；角色由 `.env` 中 `HITL_CURRENT_ACTOR_EMAIL` 和 `HITL_APPROVER_BINDINGS` 在服务端解析。这不是企业 SSO/RBAC。

## 结果反馈

**用途**：把已执行的本地采购单走到关闭，并登记真实/演示结果；适合采购跟单或计划人员。

### 采购履约

可操作活动采购单的状态流转、预计到货日、实际收货量与质检结果。页面只允许合法的下一状态，避免跳过关键环节。`QC_ACCEPTED` 会更新本地在手库存。

### 实际结果反馈

只展示可反馈的闭环候选项，用户填写实际交期、数量、缺货、质量、成本、服务水平和备注。提交人邮箱须在 `MEMORY_FEEDBACK_USERS` 白名单中。成功提交后，结果可成为后续运行的长期业务记忆候选。

### 已闭环历史结果

显示已写入结果的决策记忆；它不等同于“所有历史采购单”。

## 决策档案

**用途**：复盘当前会话刚生成的方案；适合演示或讨论。

- **需求与库存**：历史需求趋势、预测、库存位置和补货点。
- **供应商方案比较**：候选供应商的成本、质量、交期和风险相关比较。
- **情景沙盘（只读模拟）**：调整需求倍数、供应商延误天数后运行规则模拟。它不调用 LLM、Agent，不写数据库，也不创建订单。
- **完整审计**：显示当前结果包含的工作流、工具、反思、证据和执行信息。

限制：该页依赖 Streamlit 当前 session 中的结果，不是完整的历史运行检索页面；刷新或新会话后需要重新生成方案。

## 页面上没有的功能

当前 UI 没有独立的“Agent Evaluation”“自主工具”“自我反思”“知识库管理”标签页；这些能力（若运行）被收纳在决策工作台的运行记录中。离线评测通过命令行执行。
